## 비용 구분

- 메인 Codex와 ChatGPT 인증으로 실행하는 Codex 서브에이전트는 구독 이용한도를 절약하는 별도 무료 실행기가 아니다. 위임으로 메인 컨텍스트를 줄여도 총 사용량이 줄지는 측정해야 한다.
- 검증된 OpenCodex custom provider의 B.AI 추론은 B.AI 크레딧 영역이다. 이를 호출·감시·검토하는 메인의 추론은 여전히 Codex 사용량이다.
- CLI의 tokens used 39,548 / 50,394는 해당 CLI 보고값이다. B.AI 실제 청구액 또는 ChatGPT 한도 소모량으로 환산하지 않는다.
- 셸의 검색·치환·테스트·집계는 자체적으로 LLM 추론이 필요 없다. 이를 작은 단계마다 메인에게 되돌리는 방식이 불필요한 개입을 만든다.

## 권장 역할

1. 메인 Codex: 범위·계약·완료 조건 지정, 위험한 설계 판단, 핵심 diff와 검증 증거 최종 판정. 실패가 같은 태스크에서 2회면 중단·보고.
2. B.AI 워커: 제한된 파일 조사, 코드·테스트·문서 수정, 관련 검증, 오류 수정, 결과 보고를 한 묶음으로 수행. 기본 glm-5.3-flash, 필요할 때만 명시된 어려운 태스크용 모델. 재귀 위임·커밋 금지.
3. 결정적 스크립트: 상태/환경 확인, 검색, 테스트 순차 실행, 종료 코드·테스트 합계·변경 목록 기록. 성공 로그 전문을 메인에 전달하지 않음.
4. Codex 서브에이전트: 어려운 독립 검토 등 추가 추론의 가치가 큰 경우만 제한 사용. 단순 명령 실행·대기는 맡기지 않음. 비용 절감을 목표로 전체 대화 복제나 다중 동시 실행을 기본으로 삼지 않음.

## 실행 절차 제안

1. 태스크당 메인은 짧은 명세 하나를 만든다: 절대경로, 수정 허용 파일, 관련 계약, 완료 명령 원문, 금지 사항, 재시도 한도. 같은 크레이트의 연관 수정은 묶는다.
2. 워커는 명세에서 필요한 파일만 읽는다. 이전 대화 전문·전체 로드맵·불필요한 스킬/MCP를 넣지 않는 별도 워커 환경을 검증한다. 안전 제약은 유지한다.
3. 기본 실행 경로는 이미 성공한 OpenCodex → B.AI. bai-gjc는 Invalid port 원인이 해결되고 동일 소규모 과제를 통과한 뒤 대체 가능하다. 두 경로를 동시에 유지·재검증하느라 비용을 쓰지 않는다.
4. 구현·관련 테스트·수정은 워커가 끝까지 맡는다. 호출부까지 변경한 경우 해당 소비 크레이트 검사도 명세에 포함한다. 단순 파일 읽기에는 워커를 띄우지 않는다.
5. 워커 종료 후 소스 변경을 멈추고 검증 스크립트가 cargo test --workspace, cargo clippy --workspace --all-targets -- -D warnings, powershell -File build/dist-device.ps1을 순차 수행한다. 실패하면 중단하고 오류 주변만 보고한다. 같은 target 디렉터리를 쓰는 빌드를 겹치지 않는다.
6. 메인은 결과 요약과 핵심 diff만 보고 판정한다. 실패 보완은 좁은 지시로 워커에 반환한다. 사소한 결정적 수정은 직접 처리하는 편이 새 워커 기동보다 저렴하면 예외로 한다.
7. 종료 알림/완료 파일을 활용하고 5초 단위 빈 로그·진행 재확인을 없앤다. 이벤트 기반 회수가 불가능하면 30~60초 대기를 사용한다. 로그가 비어 있다는 이유로 중단하지 않는다.
8. 결과 형식은 성공/실패, 수정 파일, 명령별 종료 코드, 테스트 합계, 미해결 사항, 계약 의문, CLI 토큰 보고값으로 제한한다. 상세 로그는 파일에 둔다.

## 컨텍스트와 설정 개선 제안

- AGENTS.md에는 실행 시 반드시 필요한 짧은 규칙과 링크만 두고, 과거 사고·원인 설명·진단 레시피는 별도 문서로 이동한다. 공유 설정 금지·실기 금지·2회 실패 중단 등 제약은 축약 시 보존한다.
- HANDOFF 최상단에는 현재 상태 하나만 유지한다. 시간순 과거 상태는 task 보고서에 보관한다. 현재 문서의 서로 다른 시점의 '다음 작업' 문구는 혼동과 재조사의 원인이다.
- 사용자 전역 플러그인을 임의 제거하지 않고, 지원되는 설정을 확인하여 워커 전용 환경에서 불필요한 스킬·MCP를 제외한다. 구체적인 설정 키와 효과는 아직 검증하지 않았다.
- 메인 모델/추론 강도는 일반 운영에는 경제적인 선택, 복잡한 설계 판단에는 높은 선택을 검토한다. 현재 모델이나 전역 설정은 바꾸지 않았다.
- 작업 묶음 종료 후 짧은 인수인계로 새 작업을 시작하면 관련 없는 설치·문제 해결 대화의 누적을 줄일 수 있다. 새 작업 생성은 사용자가 요청할 때만 한다.
