## fluent-bundle 0.15 hints
- `FluentResource::try_new(String) -> Result<FluentResource, (FluentResource, Vec<ParserError>)>`
- `FluentBundle::new_concurrent(vec![langid])` creates a bundle; call `set_use_isolating(false)`.
- `bundle.add_resource_overriding(res)` lets a later resource override earlier keys (use it for
  card packs layered over the built-in).
- `bundle.add_function("JOSA", |positional: &[FluentValue], _named: &FluentArgs| -> FluentValue { .. })`
- `bundle.get_message(key)?.value()?` then `bundle.format_pattern(pattern, Some(&args), &mut errors)`.
- `FluentArgs::new()` + `args.set(name, FluentValue::from(...))`. For numbers build
  `FluentValue::Number(FluentNumber::new(f64, FluentNumberOptions { use_grouping: false, ..Default::default() }))`
  so `1234` renders as `1234`, not `1,234`. Also set `minimum_fraction_digits`/`maximum_fraction_digits`
  to 0 so `2.0` renders as `2`.
- Plural selection (`[one]`/`*[other]`) in `en.ftl` works with numbers passed as `FluentValue::Number`.
- Inside a custom function, a `FluentValue::Number` positional arg should be rendered with the
  same plain formatting (`FluentNumber::as_string`-style, no grouping) before calling `josa::attach`.
