# Task 30 — OpenCodex 분리 운영과 에이전트 절감 검토

2026-09-25. 사용자 요청: 작업 도구는 OpenCodex로 두고, 수동 중계를 포함한 추가 입력 토큰 절약과 Claude식 에이전트 활용을 검토. 이번에는 유료 추론 실험·구현 재시도·설정 변경 없이 공식 문서 및 기존 측정값만 확인했다.

## 용어 및 기존 측정 정정

기존 Task 26~29도 Codex CLI → OpenCodex localhost:10126 → 설정된 제공자/모델 경로였다. B.AI는 당시 연결된 제공자 이름이며 OpenCodex와 대체 관계인 작업 도구가 아니다. 앞으로 사용자에게는 OpenCodex 워커로 표현한다. 제공자/모델 변경은 이번 요청으로 추정해 실행하지 않는다.

41,199 및 32,606은 CLI turn.completed의 input_tokens 보고값이다. 도구 왕복을 포함한 실행의 보고값이며 첫 요청 프롬프트 크기라고 단정하지 않는다. 동일 읽기 과제 1회씩에서 약20.86% 줄었지만 캐시도 달랐고 실제 비용/ChatGPT 한도 감소율은 미측정이다. 단순 파일 읽기는 본래 셸만으로 처리하면 되며 LLM 비교는 실험용이었다.

## 권장: 사람이 중계하는 두 단계 운영

1. Codex에서 목표, 허용 파일, 관련 계약, 완료 명령, 금지 사항을 포함한 짧은 태스크 파일을 만든 뒤 응답을 끝낸다.
2. 사용자가 별도 OpenCodex 경유 작업 세션에서 그 태스크 경로를 전달한다. 전체 Codex 대화·긴 인수인계는 복사하지 않는다. 새로 생성한 미검증 Task29 런처는 사용하지 않는다.
3. OpenCodex 작업 세션에서 구현·관련 검사·오류 수정을 한 묶음으로 수행하고 결과 파일에 요약한다. 기본 작업자는 1개, 수정 범위가 겹치는 동시 작업 금지.
4. 사용자는 완료/실패 때만 Codex에 결과 파일 경로를 전달한다. 로그를 붙여넣지 않는다.
5. Codex는 요약과 필요한 diff/검증 증거만 읽어 최종 판정한다. 설계 결정이 필요하거나 2회 실패했을 때만 중간 개입한다.

장점: OpenCodex 실행 중 Codex 부모 세션의 반복 추론/감시가 없다. 양쪽 세션에 긴 대화 이력을 공유하지 않아도 된다. 사람의 개입은 착수와 회수 두 지점 중심이다. 한계: OpenCodex 내부의 모델 호출·컨텍스트 비용 및 현재 제공자 시간 초과는 별도로 남는다. 연결을 끊는 것만으로 모든 입력 토큰이 줄지는 않는다.

## 추가 절감 우선순위

- 셸로 되는 읽기·검색·정해진 검사·집계에는 LLM을 호출하지 않는다. 실패 로그 해석이 필요할 때만 좁은 오류 범위를 모델에 전달한다.
- Task 패킷은 우선 목표 1~2천 토큰, 필수 계약은 길이보다 우선. 결과는 우선 30줄 이내로 목표를 두되 명령/exit/실패/미확인 사항을 생략하지 않는다. 이 숫자는 운영 목표이지 보장값이 아니다.
- 작업자 규칙에는 실제 작업 제약만, 메인의 위임/회계/과거 장애 설명은 필요할 때 읽는다. 위임 금지/실기 금지/공유설정 보호 등 핵심 제약은 유지한다.
- 양쪽 모두 작업 묶음마다 새 컨텍스트로 시작한다. 같은 결함을 보완할 때는 짧은 후속 지시로 기존 작업자를 이어 불필요한 재탐색을 막고, unrelated 태스크에 그 이력을 넘기지 않는다.
- 먼저 파일 경로/심벌 인덱스를 찾아 필요한 범위만 읽는다. 전체 repo 및 full diff를 매번 읽지 않는다.
- worker 전용 최소 도구 구성은 별도 짧은 검증 대상으로 남긴다. 기존 plugin 제외만의 측정 효과는0.21%였다. CLI 기본 시스템 프롬프트까지 제거한 초경량 에이전트 효과는 검증하지 않았으며 안전장치를 없애는 방법은 권하지 않는다.
- 메인에서 지나치게 잦은 실행 확인을 없애는 것이 최우선. 수동 중계는 새 자동화 구현 비용 없이 이를 달성할 수 있다.

## Claude식 에이전트의 실제 의미

Claude Code의 non-fork subagent는 독립 컨텍스트에서 작업 명세를 받아 시작하고 결과를 메인으로 반환한다. fork는 부모 대화를 상속한다. 작업에 부모 전체 맥락이 필요한 경우 fork 캐시가 이점일 수 있으므로 무조건 fresh가 싸다고 단정하지 않는다.

Codex도 컨텍스트/작업 분리가 가능하다. 현재 이 대화의 도구에는 fork_turns="none"이 있어 부모 대화 없이 명세만 넘길 수 있다. 단 시스템/도구/환경 컨텍스트까지 사라지는 뜻은 아니다. 이 매개변수를 OpenCodex CLI의 공통 설정 키로 오해하면 안 된다.

OpenAI 공식 문서는 서브에이전트가 개별 모델·도구 작업을 수행하므로 유사한 단일 에이전트 실행보다 토큰을 더 소비할 수 있다고 명시한다. 따라서 Codex 계정 내 다중 에이전트는 무료 한도 우회가 아니다. 메인 컨텍스트 보호와 병렬 속도 개선은 총 토큰 절약과 별개다.

절감에 적합한 분업: 읽을 자료가 많은 한정 조사/독립 리뷰를 새 컨텍스트의 작업자 1개에 맡기고 요약만 회수. 필요시 저비용 모델을 명시 선택하되 품질/수정 횟수까지 평가. 비권장: 전체 대화를 상속한 다수 작업자, 단순명령마다 새 에이전트, 재귀 위임, 같은 파일에 동시 수정.

## OpenCodex와 Codex 자동 연동

OpenCodex 제작자 문서에는 v1/base/v2 에이전트 서피스, 위임 모델과 추론 강도 설정이 있다. 따라서 자동 분업의 지원 자체는 확인된다. 하지만 native ChatGPT에서 routed 모델로 v2 태스크를 넘기는 경우 암호화된 태스크 전달/복구 제약이 있다. 최신 웹 문서의 동작이 설치된2.64.0에서 동일하다고 검증하지 않았다. 이번에 이 경로를 켜거나 전역 라우팅을 변경하지 않는다.

추천 순서: 수동 중계로 작은 실작업 성공 → 작업자1개의 좁은 명세와 보고 형식 정착 → 필요할 때만 자동 위임 호환성 검증. 지금은 미완성 자동 실행기 수리를 절감 작업의 전제조건으로 삼지 않는다.

## 측정 기준

메인 계정 사용량, OpenCodex 경유 모델의 input/output/cached 토큰, 재시도 수, 정답/검증 결과를 구분한다. 전체 입력 토큰과 비용을 섞지 않는다. 작업당 Codex 사용자 왕복2회(명세/검토)를 우선 목표로 하며 오류/사용자 변경 요청은 별도 기록한다. 계정 한도는 타 작업과 리셋 영향을 받으므로 단독 작업 청구량으로 해석하지 않는다.
