## 순서·선택·이동·썸네일·텍스처 반납

- **순서/선택**: 입력 순서와 mtime은 결과에 관여하지 않는다(컴포넌트가 `StateSlot`에서 번호와
  썸네일 경로만 추린다). 정렬은 번호 오름차순, 기본 선택은 최대 번호. `selected_kind()`는
  번호 상태가 없으면 `None`.
- **이동**: 좌/우 모두 양끝에서 wrap. 0개면 아무 일도 없고, 1개면 제자리다.
- **스트립**: 선택 카드는 안전 영역 중앙에 고정되고, 좌우 이웃을 먼저 그린 뒤 선택 카드를
  마지막에 그려 위에 온다. 스트립은 **고리**다 — 마지막 다음은 처음이므로 선택 옆에 보이는
  카드가 곧 좌/우로 이동할 카드다. 2개일 때 같은 카드가 양쪽에 겹치지 않게 왼쪽만 그린다.
  640 폭 안전 영역에서는 한 칸 이웃까지만 들어가고(두 번째 칸은 왼쪽으로 162px 벗어난다)
  안전 영역을 벗어나는 카드는 아예 그리지 않는다.
- **카드**: 밝은 프레임(선택 INK, 이웃 INK_DIM), 4:3 그림 영역, 아래 번호 라벨.
  라벨은 `LABEL_INK`(어두운 색)로 그려 프레임 위에서 읽힌다(시도 2 수정).
  그림은 4:3 영역 안에서 비율을 유지한 채 한 축을 채우고 가운데 정렬되며, 남는 자리는
  어두운 plate가 보인다. 이웃 그림은 알파 0.55로 그려 선택 카드가 도드라진다.
- **썸네일 폴백**: 파일이 없거나 디코드 실패면 그림 영역 안쪽에 중립 회색 판을 그린다.
  실패도 캐시에 남기므로 프레임마다 디스크를 다시 읽지 않는다(테스트가 첫 프레임 뒤 파일을
  유효한 PNG로 바꿔도 다시 읽지 않음을 확인).
- **텍스처 반납**: 캐시는 12개 상한 + LRU 방출(방출 시 `canvas.free`), `clear(canvas)`가
  남은 텍스처를 모두 반납한다. 어떤 텍스처도 두 번 해제되거나 남지 않는다(테스트).
- **빈 상태**: 카드 대신 기존 `states-empty` 문구를 스트립 자리에 그린다. `selected_kind()`는
  계속 `None`이다. 같은 사실을 두 번 말하는 메시지를 새로 만들지 않으려고 재사용했다.
- **새 메시지 2개**: `state-switcher-title`("Save states"/"세이브 스테이트"),
  `state-slot`("Slot { $n }"/"{ $n }번 슬롯"). 힌트는 기존 `hint-select`/`hint-back` 재사용.

## 남은 항목과 계약 의견

- 이 태스크는 UI 컴포넌트만 만든다. `App` 화면 변형, 인게임 메뉴에서의 진입, 상태 로드·저장,
  30초 undo, 삭제, 링 정책은 계약대로 손대지 않았다. 스위처는 아직 실행 경로에서 호출되지 않는다.
- "이웃 카드 표시"를 고리로 해석했다. 계약은 이동이 wrap한다고만 정하고 표시 순서는 정하지
  않았는데, 고리가 아니면 끝에서 좌/우를 눌렀을 때 화면에 없던 카드로 건너뛰어 보인다.
  1개 슬롯이면 카드 1장만, 2개면 다른 카드 1장이 왼쪽에만 그려진다.
- `draw`가 `&mut self`인 것은 지연 캐시 때문이다(`LabelCache::art`와 같은 이유). 다른 메뉴는
  `&self`라 여기만 다르다.
- 썸네일 디코드는 그리는 크기의 2배(336×252)까지만 내려 받는다(`label.rs`의 MAX_OVERSAMPLE과
  같은 취지). 스위처는 카드 텍스처를 최대 3장만 동시에 보지만, 고리를 한 바퀴 돌면 방출된
  그림을 다시 디코드할 수 있다 — 상한과 반납이 지켜지는지를 테스트로 고정했다.
- 힌트 줄에는 좌/우 안내를 넣지 않았다. 계약이 기존 select/back 힌트를 쓰라고 했고 새 메시지는
  최소로 두라고 했다.
- 골든 스크린샷이나 실기 확인은 범위 밖이라 하지 않았다. 검증은 `RecordingCanvas` 기하 기준이다.
- 실행 시간: 시도 1 약 26분 + 시도 2 약 10분. 모델 토큰·비용 정보는 이 도구가 노출하지 않아 `unavailable`.
