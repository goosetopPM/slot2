# Task 38 최종 판정 — 통과

2026-09-25 Codex 검토 결과, `tasks/38-reversible-state-delete-store.md`의 계약을 충족했다.

## 확인한 내용

- 불투명 `StateBackup`은 원래 카드 루트·카트·번호, 상태 원본 바이트와 선택적 PNG 원본 바이트를
  보유하고 `kind()`만 공개한다.
- `take_state`는 Resume을 거부하고, 상태가 없으면 고아 썸네일을 건드리지 않은 채 `None`을
  반환하며, 전체 백업을 확보한 뒤 번호 상태와 썸네일을 제거한다.
- 삭제 중 상태 제거가 실패하면 먼저 제거한 썸네일을 원자 쓰기로 되돌리려 시도한다.
- 복원은 다른 카드 루트와 기존 state/png 충돌을 쓰기 전에 거부해 새 파일을 덮어쓰지 않는다.
- 썸네일을 원자적으로 먼저 복원하고 `.state`를 마지막에 써 목록 가시성 경계를 지킨다.
- 최종 상태 쓰기가 실패하면 그 시도가 만든 썸네일을 제거하며, 참조형 API라 같은 백업으로
  다시 시도할 수 있다.
- 정상·무썸네일·손상 PNG가 바이트 단위로 왕복하고 성공 뒤 재복원은 충돌로 거부된다.
- 기존 영구 삭제, 상태 번호, 저장 형식과 Resume 동작은 유지된다.
- 허용 파일 밖의 Task 38 변경은 보고되지 않았고 실제 대상 변경 목록과 일치한다.

신규 테스트는 원본 바이트 왕복, Resume 보호, 다른 카드 거부, state/png 각각의 충돌, 성공 후
중복 복원 거부, 상태 쓰기 실패 시 썸네일 정리와 백업 재사용을 검증한다. `git diff --check`도
종료 0이며 CRLF 안내 외 공백 오류는 없다. 보고서와 구현·테스트가 일치해 검증을 중복 실행하지
않았다.
