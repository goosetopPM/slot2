# SLOT2 RG SP 실기 인수 체크리스트 (Task 120)

> ## 상태: `NOT RUN`
>
> 이 문서의 어떤 항목도 아직 실행되지 않았습니다. 결과 칸은 모두 `NOT RUN`입니다.
>
> 이 체크리스트는 **RG SP 실기에서 사용자 본인만** 수행하고 서명할 수 있습니다. Gajae, Codex, host evidence,
> hosted CI는 어떤 항목도 `PASS`로 대신 채우거나 서명할 수 없습니다. 이 문서의 절차는 사람이 손으로 수행하는
> 것이며, 어떤 도구나 에이전트도 이 문서의 절차를 자동으로 실행하지 않습니다.
>
> 이 문서는 **정확히 커밋되어 푸시된 리비전과, 그 리비전의 성공한 hosted CI device artifact**를 요구합니다.
> 현재의 dirty/미커밋 로컬 트리는 device-test 입력으로 쓸 수 없습니다. **태그와 릴리스는 이 단계에서 요구되지도,
> 허용되지도 않습니다.**

## 0. 범위와 이미 검토된 host evidence의 구분

- 이 체크리스트의 대상 기기는 **RG SP(`BASEOS_TARGET=rgsp`, 720x480)** 하나입니다. 이 통과는 다른 기기나 다른
  지오메트리에 대한 지원 검증이 아니며, 지원 기기 범위를 넓히지 않습니다(README §2).
- 이미 검토가 끝난 **host evidence**는 다음과 같습니다. 참고 자료로 쓰되, 아래 표의 어떤 `PASS`도 대신할 수
  없습니다.
  - Task117: PC GL 창에서 3개 지오메트리의 선반·삽입/꺼내기 화면.
  - Task118: 720x720 GB 선반에서 세로로 긴 카트가 `A play` hint를 가리던 결함의 수정 후 호스트 재확인.
  - Task119: 720x480에서 15개 시나리오 x 영어/한국어 = 30장의 메뉴·대화상자·토스트 화면, workspace 테스트
    979 passed/0 failed, clippy warning 0.
- host evidence는 **실기 결과가 아닙니다.** 실기에서 직접 본 것만 `PASS`가 될 수 있습니다. host evidence로
  확인된 항목도 실기에서는 화면·입력·오디오·성능·전원·카드 마운트 관점에서 다시 확인합니다.
- 이 체크리스트의 **기대 결과**는 모두 "현재 구현이 보증하는 동작"이 아닙니다. 출처에 따라 셋으로 나뉩니다.
  1. **현재 동작으로 서술된 것**: `README.ko.md` §1~§7에 지금 하는 일로 적혀 있거나, 이미 검토가 끝난
     Task117~119가 확인한 동작입니다. 기대와 다르면 `FAIL`입니다.
  2. **미검증 릴리스 인수 목표**: `docs/MILESTONES.md` M4/M6에서 아직 체크되지 않은 항목입니다. 특히
     뚜껑(9.1절)과 HDMI(9.4절)는 구현이 아직 없거나 다를 수 있어 이번 실기에서 처음 드러날 수 있고,
     그때는 `FAIL` 또는 `BLOCKED`로 남깁니다.
  3. **선택/범위 밖 관찰**: 선택 항목과 10절의 사용 불가 표시 확인입니다. 문서화된 대로 동작하면 `SKIP`이
     정상이며 제품 실패가 아닙니다.
- 어느 경우든 기대와 다르게 동작하면 그대로 기록하고, `FAIL`이면 13절 결함 양식에 남깁니다.
- 아래 **사용 불가/범위 밖** 항목(Sync, 밝기, 블루라이트, 기본 화면 설정, 부팅 로고, 사용자 셰이더 파일, 압축
  ROM, RG28XX)은 문서화된 대로 "사용할 수 없음"이 정상입니다. 이것을 제품 실패로 기록하지 않습니다.

## 4. 결과 표기 규칙

- 각 행의 **결과** 칸은 실행 전 기본값이 `NOT RUN`입니다. `NOT RUN`은 완료된 결과가 아니며, 종료 시점에 필수
  항목이 `NOT RUN`으로 남아 있으면 인수는 실패입니다.
- 완료된 결과로 적을 수 있는 값은 다음 네 가지뿐입니다.
  - `PASS`: 절차를 수행했고 기대 결과와 일치했으며 증거를 남겼다.
  - `FAIL`: 수행했고 기대 결과와 다르다. 13절 결함 양식에 적는다.
  - `SKIP`: 수행하지 않았고, 그 이유를 증거/메모 칸에 적었다.
  - `BLOCKED`: 수행할 수 없었다(예: 2절 게이트 미충족, 카드 없음). 막은 원인을 적는다.
- **host evidence는 어떤 행의 `PASS`도 대신하지 못합니다.**
- **필수 항목**은 `PASS`여야 합니다. 필수 항목의 `SKIP`은 종료 기준에서 실패로 취급합니다. **선택 항목**은
  `PASS`이거나 명시적 `SKIP` 이유가 있으면 됩니다.
- 선택 항목은 ID에 `OPT`가 들어 있거나, 해당 절 제목에 `(선택)`이 붙어 있습니다.
- 다음 ID 묶음은 모두 릴리스 차단 필수 항목입니다: `GATE-*`, `SAFE-01`, `SAFE-03`~`SAFE-06`, `INST-*`,
  `IDN-*`, `SHF-*`, `INP-*`, `PLT-*`, `COR-*`, `STT-*`, `TIM-*`, `CHT-*`, `DSP-*`, `L10-*`, `AUD-*`,
  `LID-01`~`LID-04`, `PWR-*`, `STB-*`, `UNAV-01`~`UNAV-07`.
- `SAFE-02`는 **조건부**입니다. 시나리오 B(11절)를 수행할 때만 필수이고, 시나리오 B를 이유와 함께
  `SKIP`하면 `SAFE-02`도 `SKIP`으로 남습니다. 이 조건부 `SKIP`은 필수 `NOT RUN`을 남기지 않으므로
  새 카드 전용 인수를 막지 않습니다.

## 9. 세션 3 — 뚜껑, 전원, 안정성, HDMI

### 9.1 뚜껑 (필수, `LID-OPT-01`은 선택)

M4는 뚜껑 계약을 "닫으면 스테이트 저장 + 화면 끔, 3분 뒤 전원 끔, 3분 전에 열면 복귀"로 기록하지만, 그 작업은
`docs/MILESTONES.md` M4에서 **아직 체크되지 않았습니다.** 따라서 `LID-01`~`LID-04`는 이미 확인된 제품 동작이
아니라 **미검증 릴리스 인수 목표**이며, 구현이 없거나 다르면 이번 실기에서 처음 드러나 `FAIL` 또는 `BLOCKED`로
남을 수 있습니다. host evidence나 CI 결과는 이 실기 결과를 대신 채우지 못합니다.

| ID | 절차 | 기대 결과 | 결과 | 증거/메모 |
| --- | --- | --- | --- | --- |
| LID-01 | 게임 실행 중 뚜껑을 닫는다. | 화면이 꺼지고 상태가 저장된다. | NOT RUN | |
| LID-02 | 뚜껑을 다시 연다(닫은 뒤 3분이 지나기 전). | 게임으로 복귀하고 이어서 플레이할 수 있다(M4의 미검증 인수 문장). 동작이 없으면 `FAIL` 또는 `BLOCKED`로 기록한다. | NOT RUN | |
| LID-03 | 뚜껑 닫기와 열기를 2~3회 반복한다. | 왕복할 때마다 게임 진행이 유지되고, 화면이나 소리가 깨지지 않는다. | NOT RUN | |
| LID-04 | 뚜껑을 닫은 뒤 **3분 임계값보다 짧게(예: 30~60초)** 기다렸다가 다시 연다. 3분을 넘겨 기다리는 동작은 `LID-OPT-01`에서 따로 본다. | 3분이 지나기 전에 열었으므로 화면이 다시 켜지고 게임이 그대로 이어지며, 처음부터 다시 시작하지 않는다. 반대로 이 시점에 이미 전원이 꺼져 있으면 그 사실을 그대로 기록한다. | NOT RUN | |

#### 9.1.1 (선택, 여분 카드 전용) 3분 전원 끔 관찰

이 소절은 선택이며, **여분 카드에서만** 수행합니다. 사용자가 수행하기로 명시적으로 선택하지 않았으면 이
소절 전체를 `SKIP`하고 이유를 적습니다. 주 사용 카드로는 수행하지 않습니다. `LID-04`의 3분 미만 왕복과는
별개로, 3분 임계값을 넘긴 뒤의 의도된 동작(전원 끔)을 보는 선택 관찰입니다.

| ID | 절차 | 기대 결과 | 결과 | 증거/메모 |

## 14. 종료 기준 (exit criteria)

- 릴리스 차단 **필수 항목이 모두 `PASS`**여야 합니다. **선택 항목**은 `PASS`이거나 명시적 `SKIP` 이유가 있어야
  합니다. 필수 항목이 `NOT RUN`이나 `BLOCKED`로 남아 있으면 인수는 실패입니다.
- 해결되지 않은 `BLOCKER` 또는 `MAJOR` 결함이 남아 있지 않아야 합니다.
- 새 카드 시나리오(6절)가 **정확히 커밋되고 CI가 만든 artifact 정체성**으로 통과해야 합니다. dirty 로컬
  빌드나 다른 SHA의 artifact로 통과한 결과는 인정하지 않습니다.
- 시나리오 A(6절, 새 카드)는 **필수**입니다. 시나리오 B(11절, 기존 카드 마이그레이션)는 적합한 레거시
  테스트 카드가 없으면 **이유와 함께 `SKIP`**할 수 있으며, 그 `SKIP`은 실패가 아닙니다.
- 시나리오 B를 수행하기로 한 경우에만 `SAFE-02`(카드 밖 전체 백업)가 필수이고, 검증한 백업과
  `docs/MIGRATION.ko.md` §6 롤백 경로는 `PASS` 없이는 넘길 수 없는 하드 게이트입니다. 시나리오 B를
  `SKIP`하면 `SAFE-02`도 `SKIP`으로 남고, 이 때문에 필수 `NOT RUN` 행이 생기지 않습니다.
- 마이그레이션은 **실제로 수행한 경우에만** 인수됩니다. 수행하지 않았다면 명시적으로 `SKIP`으로 남고, 통과로
  주장하지 않습니다.
- 최종 실기 인수 서명은 **사용자만** 할 수 있습니다. Gajae, Codex, host evidence, hosted CI는 대신 서명할 수
  없습니다.
- 실패가 있으면 좁은 범위의 수정 태스크를 만들고, 영향을 받은 검사와 함께 그때 이름을 붙인 회귀 검사를 다시
  실행합니다.
- **완전 통과도 태그나 릴리스를 승인하지 않습니다.** 태그와 릴리스는 이후 별도의 명시적 사용자 지시가 있어야
  합니다.
