# Task 47 검토 결과 — 읽을 수 없는 게임 설정 덮어쓰기 거부

## 판정

**성공** — 누적 호출 1/2.

## 검토 내용

- `Card::read_settings`의 관대한 정책은 유지되어 누락·손상·읽기 실패가 카드 탐색과 실행을
  막지 않는다.
- `Card::write_settings`는 기존 ini를 `Ini::load(&path)?`로 읽으며, 읽을 수 없는 기존 경로를
  빈 설정으로 오인해 덮어쓰지 않는다.
- invalid UTF-8 파일에 비기본 설정을 쓰거나 기본값으로 지우려는 시도는 모두 오류를 반환하고
  원본 바이트를 그대로 보존한다.
- 설정 파일 경로가 디렉터리인 경우도 쓰기와 삭제를 거부하며 경로를 보존한다.
- 파일 누락, 정상 라운드트립, 알 수 없는 키 보존, 기본값 복원에 따른 파일 제거는 유지된다.
- Display 메뉴 경로에서도 읽을 수 없는 ini는 관대한 정책에 따라 기본 행으로 열리지만, A로
  변경을 저장하면 실패 토스트를 표시하고 선택 행·Session 배율·원본 바이트를 보존한다.

## 작업자 검증 증거

- 결함 동작을 임시 복원했을 때 신규 저장소와 App 회귀 테스트가 각각 실패하는 음성 대조 확인
- `cargo fmt --all -- --check`: 종료 코드 0
- `cargo test -p slot2-store`: 종료 코드 0, card 19개 포함 0 failed
- `cargo test -p slot2 --test display_menu_app`: 종료 코드 0, 9 passed
- `cargo clippy -p slot2-store -p slot2 --all-targets -- -D warnings`: 종료 코드 0
- 최종 검증 뒤 코드 변경 없음

충분한 작업자 증거가 있어 동일 테스트는 다시 실행하지 않았다. 관련 파일의
`git diff --check`는 종료 코드 0이다.

## 남은 위험과 후속

- 파일 경로가 디렉터리인 테스트는 fallible read 단계에서 먼저 실패하므로, 그 사례가
  `remove_file` 오류 분기 자체를 직접 실행하지는 않는다. 권한 기반 실패는 플랫폼마다 달라
  휴대용 테스트로 추가하지 않았다. 오류 전파 구현과 정상 삭제 검증은 유지되어 비차단으로 본다.
- 다음 기능 태스크 지시서는 아직 작성하지 않았다.
