# SLOT2

SLOT2는 Anbernic H700 계열 휴대기에서 [BaseOS](https://github.com/pvaibhav/BaseOS) 위에 올려 쓰는 카트리지
메타포 프론트엔드입니다. GB, GBC, GBA, NES, SNES, MD, SMS 게임을 인프로세스 libretro 코어로 카트리지 선반에서
실행합니다. [brandonkowalski/slot](https://github.com/brandonkowalski/slot)(MIT)에서 출발해 그 위에 다시
만든 프로젝트입니다.

**English document: [README.md](README.md)**

## 1. 개요와 프로젝트 상태

SLOT2는 **정식 공개 전(pre-release)** 프로젝트입니다. 공개 릴리스는 아직 배포된 적이 없고, 태그 릴리스도
실행된 적이 없으며, GitHub 다운로드 페이지도 없습니다. 릴리스 자산은 아래에서 설명하는 파일 구성이며,
프로젝트는 그 구성을 로컬에서 만들고 검사할 수 있습니다.

- 개발 기준 기기이자 지금까지 실기로 검증한 유일한 기기는 **RG SP**입니다. 아래의 다른 기기 프로파일은
  BaseOS의 기기 데이터를 근거로 구현되어 있지만 **실기 검증이 완전히 끝나지는 않았습니다.**
- 구현과 자동 로컬 검증의 범위는 넓습니다. 워크스페이스는 CI에서 빌드·테스트·린트·포맷 검사를 거치고, 카드
  트리는 패키징 전에 항목별로 검증되며, 패키징과 배포 단계에도 자체적인 오프라인 검사가 있습니다.
- 아직 남아 있고 아래 어디에서도 주장하지 않는 것: 호스팅 환경에서의 태그 릴리스 실행, 새 카드 첫 사용자
  실사용 확인, 여러 기기에 걸친 실기 검증입니다.

지금 SLOT2가 하는 일을 간단히 정리하면 다음과 같습니다.

- 플랫폼별 카트리지 선반과 카트·포트 이미지;
- 플랫폼에 코어가 둘 이상 있는 경우(GB, GBC, GBA) 게임별 코어 선택;
- 마지막 resume 또는 번호가 있는 상태에서 이어하기, 또는 요청 시 처음부터 시작하기;
- 세이브 데이터, 섬네일이 있는 번호별 상태, 빠른 저장·빠른 불러오기, 상태를 불러오기·삭제·삭제 되돌리기까지
  하는 상태 전환기;
- 되감기(rewind)와 빨리 감기(fast-forward);
- 게임별 RetroArch 형식 치트 파일을 읽어 적용하는 치트;
- 화면 배율 행(플랫폼 기본값, integer, aspect-fit, fill), 내장 셰이더 프리셋, 잘라내는 플랫폼의 오버스캔
  조절, 오버레이 켜기/끄기;
- 영어와 한국어 내장, 카드 언어 팩, 시간대 설정, 볼륨;
- 개발용 PC 미리보기 창.

아직 없고, 흉내내지 않고 UI에서 사용 불가로 표시하는 것:

- **동기화(Sync)** (데스크톱 앱과 Wi-Fi/SFTP 전송): 백엔드가 없습니다. 설정 메뉴의 Sync 행은 열 수 없습니다.
- **밝기**와 **블루라이트 조절**: 백엔드가 없습니다. 기기 메뉴의 해당 행은 사용 불가로 표시되고 선택할 수
  없습니다.
- **사용자 셰이더 파일**: 내장 프리셋만 있고 사용자 GLSL 파일은 지원하지 않습니다.
- **압축 ROM**(`.zip`, `.7z`, `.gz` 등): 지원하지 않습니다.
- **RG28XX**: 이 프로젝트의 범위가 아닙니다.
- 설정 메뉴의 **기본 화면 설정(Display defaults)** 과 **부팅 로고(Boot logo)** 행은 아직 뒤에 화면이 없습니다.

## 2. 지원 기기, 플랫폼, 코어

BaseOS는 부팅한 기기 이름을 `/etc/baseos-release`에 `BASEOS_TARGET=<id>` 형태로 남기고, SLOT2는 그 id를 읽어
프로파일을 고릅니다. 존재하는 프로파일은 다음과 같습니다.

| `BASEOS_TARGET` | 기기 | 패널 | 덮개 | 스틱 |
| --- | --- | --- | --- | --- |
| `rgsp` | RG SP (개발 기준, 실기 검증) | 720x480 | 있음 | 없음 |
| `rg34xx` | RG34XX | 720x480 | 없음 | 없음 |
| `rg34xxsp` | RG34XXSP | 720x480 | 있음 | 없음 |
| `rg35xxsp` | RG35XXSP | 640x480 | 있음 | 없음 |
| `rg35xxplus` | RG35XX Plus | 640x480 | 없음 | 없음 |
| `rg35xxh` | RG35XXH | 640x480 | 없음 | 있음 |
| `rg35xxpro` | RG35XX Pro | 640x480 | 없음 | 없음 |
| `rg40xxh` | RG40XXH | 640x480 | 없음 | 있음 |
| `rg40xxv` | RG40XXV | 640x480 | 없음 | 있음 |
| `rgcubexx` | RG CubeXX | 720x720 | 없음 | 있음 |

알 수 없는 `BASEOS_TARGET`은 덮개와 스틱이 없는 640x480 패널로 대체되고, 부팅 로그에 unknown으로 기록됩니다.
이 대체 동작은 안전한 기본값일 뿐이며, **모든 H700 기기를 지원한다는 뜻이 아닙니다.** 지원 범위는 위 표이고
RG28XX는 범위 밖입니다.

플랫폼과 코어입니다. 모든 코어는 프론트엔드 프로세스 안에서 돌고, 대체 코어는 해당 게임 메뉴에서 고르는
게임별 선택입니다.

| 플랫폼 | ROM 폴더 | 확장자 | 기본 코어 | 대체 코어 |
| --- | --- | --- | --- | --- |
| GB | `Games/GB` | `.gb` | mGBA | Gambatte |
| GBC | `Games/GBC` | `.gbc` | mGBA | Gambatte |
| GBA | `Games/GBA` | `.gba` | mGBA | gpSP |
| NES | `Games/NES` | `.nes` | FCEUmm | - |
| SNES | `Games/SNES` | `.sfc`, `.smc` | Snes9x | - |
| MD | `Games/MD` | `.md`, `.gen`, `.bin` | Genesis Plus GX | - |
| SMS | `Games/SMS` | `.sms` | Genesis Plus GX | - |

배포되는 코어는 정확히 이 여섯 개이며 [cores/required.txt](cores/required.txt)에 나열되어 있습니다.
프론트엔드는 이들을 `System/cores/`에서 찾습니다. 카드에 하나라도 없으면 실행할 수 없는 게임을 시작하는 대신
실행이 실패합니다.

ROM 인식 규칙은 의도적으로 단순합니다.

- 폴더와 확장자가 플랫폼을 결정하며, 파일 내용은 검사하지 않습니다.
- 플랫폼 폴더 안에 **직접 들어 있는 일반 파일**만 인식합니다. 하위 폴더는 검색하지 않습니다.
- 이름의 **마지막** 확장자만 대소문자 구분 없이 비교하고, 나머지는 공백·괄호·마침표·문자 체계를 포함해 그대로
  씁니다.
- 압축 ROM은 열지도 풀지도 않습니다.

SLOT2에는 **ROM과 BIOS 파일이 포함되어 있지 않습니다.** 직접 준비하셔야 합니다. 현재 코어들은 BIOS 없이
동작하고, 정당한 경로로 구한 BIOS가 있다면 프론트엔드가 찾는 위치인 `BIOS/` 바로 아래에 둘 수 있습니다. 게임을
받지 않을 곳에서 BIOS 파일을 받지 마십시오.

## 3. 새로 설치하기

> **이 문서는 새로 설치하는 경우만 다룹니다.** 이미 원본 slot이 설치된 카드에서 `System/`을 교체하는 일은
> **별도의 절차**이며 [docs/MIGRATION.ko.md](docs/MIGRATION.ko.md)에 적었습니다. 이미 쓰고 있는 카드의
> 업그레이드 안내로 이 단계를 쓰지 마십시오. **먼저 카드를 백업하십시오.** SLOT2는 세이브 데이터와 상태,
> 설정을 만들고 쓰기 때문에, 기존 카드 위에서 잘못 설치하면 그 안에 있던 것을 잃을 수 있습니다.

SLOT2는 카드를 이미징하지 않고 BaseOS도 건드리지 않습니다. [BaseOS 문서](https://github.com/pvaibhav/BaseOS)를
따라 TF1에 BaseOS를 설치한 다음, 아래처럼 그 위에 SLOT2를 올립니다.

SLOT2 릴리스 자산은 **루트가 `System/`인** zip 하나와, 그 옆에 놓이는 zip의 SHA-256을 담은 `.sha256`
사이드카입니다. 아직 공개 릴리스가 없어서 연결할 다운로드 페이지는 없습니다. zip을 가지고 있다면 모양은
아래와 같아야 하고, 사이드카로 파일이 온전히 도착했는지 확인합니다.

압축을 풀기 전에 검사하십시오. `<zip>`은 실제 파일 이름(예: `slot2-<tag>.zip`)을 대신하는 자리표시자이므로
바꿔 넣고, 사이드카를 텍스트 편집기로 열어 기대 해시를 확인하십시오.

```powershell
# Windows PowerShell: 출력된 해시를 <zip>.sha256 안의 값과 비교합니다
(Get-FileHash <zip> -Algorithm SHA256).Hash
```

```sh
# Linux: 사이드카가 sha256sum 형식이라 이 명령이 대신 검사해 줍니다
sha256sum -c <zip>.sha256

# macOS: 해시를 출력하고 <zip>.sha256 안의 값과 비교합니다
shasum -a 256 <zip>
```

카드 한 장(BaseOS와 SLOT2를 같은 TF 카드에):

1. 문서를 따라 TF1에 BaseOS를 설치합니다.
2. PC에서 BaseOS 데이터/카드 루트 볼륨을 마운트합니다.
3. SLOT2 zip의 **내용물**을 그 루트에 풉니다. 실행 파일이 정확히 `<card root>/System/frontend`에 놓여야
   합니다. `<card root>/SLOT2/System/frontend`가 되었다면 한 단계 깊게 들어간 것이므로 BaseOS가 찾지
   못합니다. `System` 폴더를 위로 옮기십시오.
4. 위 표의 플랫폼 폴더에 ROM을 복사한 뒤 카드를 안전하게 제거합니다.

카드 두 장(BaseOS는 TF1, SLOT2와 ROM은 TF2):

1. BaseOS는 TF1에 그대로 둡니다.
2. BaseOS가 지원하는 파일 시스템으로 TF2를 준비합니다. 포맷 정책은 BaseOS의 몫이며, 이 프론트엔드가 특정
   포매터나 레이블을 요구하지도, 여기서 주장하지도 않습니다.
3. zip 내용물을 TF2 루트에 풉니다. TF2에 `System/frontend`가 있어야 합니다.
4. ROM은 TF2의 `Games/<PLATFORM>` 폴더에 넣습니다.
5. 카드 두 장을 넣습니다. BaseOS는 삽입된 TF2 데이터 카드를 우선하고, 없으면 TF1 데이터 파티션을 사용합니다.
   어느 쪽이든 프론트엔드는 그 볼륨을 카드 루트로 받으므로 구성은 같습니다.

첫 실행에서 기대할 수 있는 것은 보수적으로 이 정도입니다. BaseOS가 카드 루트를 작업 디렉터리로 두고
`System/frontend`를 실행하고, SLOT2는 없는 사용자 데이터 폴더를 만들며, 선반에는 플랫폼 폴더 바로 아래에서
찾은 지원 ROM이 표시됩니다. 이것이 설계된 동작입니다. 새 카드 첫 사용자 실사용 확인은 **아직 하지
않았으므로**, 첫 부팅은 이미 검증이 끝난 안내가 아니라 확인 중인 설치로 다루십시오.

## 4. ROM 폴더와 카드 구성

```text
BIOS/
Games/{GB,GBC,GBA,NES,SNES,MD,SMS}/
Labels/{GB,GBC,GBA,NES,SNES,MD,SMS}/
Saves/
States/
System/frontend
System/cores/
System/Fonts/
System/Lang/
System/cheats/{GB,GBC,GBA,NES,SNES,MD,SMS}/
System/licenses/
Wallpapers/
```

릴리스 zip에서 오는 것은 `System/`뿐입니다. 나머지는 사용자의 것이거나 처음 사용할 때 만들어집니다.
`slot2-store`가 관리하는 세이브 데이터, 상태, 상태 섬네일, 설정은 옆에 임시 파일로 쓴 뒤 이름을 바꿔 넣는
경로로 기록합니다.

ROM 파일 이름의 **stem**(확장자를 뺀 나머지)은 그 게임에 대해 카드가 보관하는 모든 것의 열쇠입니다. 라벨
(`Labels/<PLATFORM>/<stem>.png`), 세이브 데이터(`Saves/...`), 상태(`States/...`), 게임별 설정과 치트가 모두
stem을 기준으로 합니다. 그래서 ROM 이름을 바꾸면 세이브와 라벨, 상태를 잃은 것처럼 보입니다. 새 이름은 다른
stem이기 때문입니다. ROM 이름을 바꾸려면 관련 파일도 함께 바꾸거나 백업에서 되돌리십시오. SLOT2가 대신
옮겨 주지 않습니다.

## 5. 기기 조작

선반(카트리지 목록):

| 입력 | 동작 |
| --- | --- |
| 좌 / 우 | 카트리지 선택 |
| L1 / R1 | 플랫폼 전환 |
| A (짧게) | 마지막 resume 또는 번호가 있는 상태에서 이어하기, 없으면 처음부터 |
| A (길게) | 처음부터 시작 |
| MENU (짧게) | 설정 |
| MENU (길게) | 전원 메뉴 |

게임 실행 중:

| 입력 | 동작 |
| --- | --- |
| MENU (짧게) | 게임 중 메뉴 |
| MENU (길게) | 게임을 빼고 선반으로 |
| SELECT + R1 | 다음 번호 상태로 빠른 저장 |
| SELECT + L1 | 가장 마지막 번호 상태를 빠른 불러오기 |
| R2 (길게) | 누르는 동안 빨리 감기 |
| R2 (두 번) | 빨리 감기 고정 켜기/끄기 |
| L2 (길게) | 되감기. 두 개를 함께 누르면 되감기가 빨리 감기보다 우선합니다 |

게임 중 메뉴에는 계속하기, 상태 저장, 치트, 화면, 코어, 기기, 빼기가 있습니다. 일반적인 메뉴에서는 D-pad로
이동하고 A로 확정하며 B 또는 MENU로 돌아갑니다. 예외는 상태 전환기(상태 저장)입니다. 좌우로 선택하고 A로
불러오며, X로 삭제하고 Y로 삭제한 상태를 되돌립니다(되돌리기는 30초 동안 유지됩니다). B 또는 MENU로
돌아갑니다. 기기의 볼륨 키는 게임 실행 중을 포함해 어느 화면에서든 볼륨을 바꿉니다.

코어 행은 한 플랫폼에 배포 코어가 둘 이상인 경우(GB, GBC, GBA)에만 쓸모가 있습니다. 나머지 플랫폼에서는 그
플랫폼을 실행하는 코어 하나만 보여 줍니다. 기기 행의 밝기와 블루라이트 항목은 아직 백엔드가 없어 사용 불가로
표시됩니다.

## 6. PC 미리보기와 호스트 키보드 조작

프론트엔드에는 개발용 데스크톱 백엔드가 있습니다. 720x480 창을 열고 같은 UI와 코어를 실행합니다.

```sh
cargo run -p slot2
```

카드 루트는 `SLOT2_ROOT` 환경 변수에서 읽고, 없으면 실행한 디렉터리 기준 `./sdcard`를 씁니다. `SLOT2_ROOT`를
카드 루트로 지정하거나 `sdcard` 폴더가 있는 디렉터리에서 실행하면 실제 파일로 선반을 시험할 수 있습니다.

| 키 | 버튼 |
| --- | --- |
| 방향 키 | D-pad |
| X / Z | 기기 A / B |
| S / A | 기기 X / Y |
| Q / W | L1 / R1 |
| 1 / 2 | L2 / R2 |
| Enter | Start |
| Right Shift | Select |
| M 또는 Backspace | MENU |
| Page Up / Page Down | 볼륨 올리기 / 내리기 |
| P | 전원 |
| Escape | 미리보기 종료 |

미리보기는 개발 편의 기능이지 기기가 아닙니다. 휴대기의 오디오 출력, 기기 자체의 조작, GPU, 전원 관리, 카드
마운트, 성능은 **검증하지 않습니다.** 그 항목들은 실기가 필요합니다.

## 7. 문제 해결 / FAQ

- **선반이 비어 있습니다.** ROM이 올바른 플랫폼 폴더(`Games/GB`, `Games/GBA` 등) 바로 아래에 있는 압축되지
  않은 일반 파일이고 지원 확장자를 쓰는지, 그리고 프론트엔드가 보는 카드 루트가 복사한 그 카드인지
  확인하십시오.
- **프론트엔드가 시작하지 않습니다.** 실행 파일이 카드 루트 아래 정확히 `System/frontend`인지
  (`SLOT2/System/frontend`가 아닌지), 그리고 실행 파일만이 아니라 릴리스 트리 전체를 풀었는지 확인하십시오.
- **코어가 없다는 메시지가 나옵니다.** 릴리스 전체를 다시 푸십시오. `System/cores/`에 배포 코어가 모두
  있어야 합니다. SLOT2는 찾지 못한 코어로 게임을 시작하지 않습니다.
- **GB, GBC, GBA 게임 동작이 이상합니다.** 게임 중 메뉴에서 코어를 골라 해당 플랫폼의 대체 코어(Gambatte는
  GB/GBC, gpSP는 GBA)를 시험해 보십시오. 코어에 따라 실제로 동작이 다른 게임이 있습니다.
- **ROM 이름을 바꾼 뒤 세이브나 상태가 사라진 것처럼 보입니다.** stem 기준으로 저장되므로 이름을 원래대로
  돌리거나 관련 파일도 함께 바꾼 뒤 백업에서 복구하십시오. 자동 마이그레이션은 없습니다.
- **설정을 쓸 수 없습니다.** 동기화, 밝기, 블루라이트 조절은 백엔드가 아직 완성되지 않아 해당 행을 쓸 수
  없습니다. 사용자 셰이더 파일도 지원하지 않으며 내장 프리셋을 씁니다.
- **진단 정보.** `/tmp/frontend.log`는 BaseOS가 프론트엔드의 출력을 보관하는 곳이며 휘발성입니다. 부팅 보고서의
  카드 사본은 `System/slot2-diag.txt`이고, 기기에서 터미널 없이 카드 리더로 볼 수 있습니다.

## 8. 번역과 프로젝트 문서

언어를 추가할 수 있고, 일부 문자열만 번역해도 전체를 번역해도 됩니다. **기여를 환영하며, 절차 전체가

방법이 있습니다.

- [docs/TRANSLATING.md](docs/TRANSLATING.ko.md) - UI 번역과 언어 팩.
- [docs/MIGRATION.ko.md](docs/MIGRATION.ko.md) - 원본 slot 카드를 SLOT2로 옮기기.

- [docs/DECISIONS.md](docs/DECISIONS.md) - 그 결정들과 그 이유.
