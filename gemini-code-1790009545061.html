slot 프로젝트 기기 빌드 및 환경 구성 현황 보고서

1. 개요

  • 목표: Anbernic RG35XXSP 기기용 Rust 기반 커스텀 런처/펌웨어 slot의 ARM64 크로스 컴파일, 외부 RetroArch CLI 인자 파서 연동 및 실기기 배포 검증
  • 작업 환경:
    • 호스트: Windows 11 PC (N100 미니 PC, SSH 세션)
    • 빌드 환경: Docker (rust:1-bullseye linux/arm64 에뮬레이션 컨테이너)
    • 프로젝트 경로: C:\Users\gyuha\slot-2

2. 작업 완료 내역

2.1 외부 런처 및 CLI 파서 연동 (RetroArchLauncher)

  • slot 바이너리가 게임 카트리지 선택 시 RetroArch를 외부 프로세스로 구동할 수 있도록 런처 생명주기 및 동적 CLI 인자 파서 구현.
  • SD 카드의 System/retroarch_args.txt 파일에 정의된 커스텀 플래그(예: -v, --appendconfig 등)를 파싱하여 구동 시 전달하도록 구조화.

2.2 ARM64 타깃 크로스 컴파일 완료

  • 빌드 산출물: target-device/device/slot
  • 파일 규격: 5,595,912 바이트 (약 5.59MB), ELF64 (AArch64 / ARM64 Linux, glibc 2.31+ 호환)
  • 빌드 명령어: 
    docker run --rm --platform linux/arm64 -v "${PWD}:/src" -w /src rust:1-bullseye cargo build --release

2.3 MicroSD 파일시스템 및 ROM 탐색 규칙 확인

  • 런처/시스템 디렉터리: SD:/System/
    • slot: 빌드된 실행 바이너리
    • retroarch_args.txt: (선택) RetroArch 구동 시 추가 인자
    • *_libretro.so: mgba_libretro.so, gpsp_libretro.so 등 코어 라이브러리
  • ROM 최상위 디렉터리: SD:/Roms/가 아닌 SD:/Games/
  • 플랫폼 분류 원칙:
    • ROM 헤더 스니핑이 아닌 폴더 경로와 파일 확장자만으로 플랫폼 매핑.
    • GBA: Games/GBA/*.gba
    • GB: Games/GB/*.gb
    • GBC: Games/GBC/*.gbc
  • 카트리지 개수 규칙 ("Dedicated Device" 특성):
    • ROM이 1개만 등록되면 선반(Shelf) UI를 건너뛰고 카트리지를 즉시 슬롯에 장착/실행하는 전용 머신 모드로 진입.
    • 정상적인 선반(Shelf/카루셀) UI 및 카트리지 목록을 보려면 최소 2개 이상의 ROM 필요.

3. 현안 및 트러블슈팅 진행 상황

3.1 1번 슬롯(TF1) 단독 설치 시 부팅/스캔 오류

  • 현상: Games/GBA/에 ROM을 넣었음에도 인식이 되지 않거나 1번 슬롯 환경에서 구동 오류 발생.
  • 추정 원인:
    1. 마운트 지점 불일치: Anbernic 리눅스 배포판의 TF1 파티션 마운트 경로와 crates/slot/src/root.rs에 정의된 SD 루트 경로(DIRS, /mnt/...) 불일치 가능성.
    2. 단일 ROM 실행 충돌: ROM이 1개만 들어있어 즉시 부팅을 시도하다 코어 라이브러리 부재 등으로 크래시 발생 가능성.
    3. 압축 포맷 미지원: .zip 등 압축 파일은 미인식, 순수 바이너리(.gba) 필수.
