# SLOT2 결정 기록 (Decision Log)

브레인스토밍(2026-09-22)에서 확정한 사항. 번호는 이후 문서·이슈에서 `D-xx`로 참조한다.
뒤집을 때는 삭제하지 말고 "폐기됨 → D-yy" 로 표시한다.

| ID | 결정 | 근거 요약 |
|---|---|---|
| D-01 | **BaseOS(pvaibhav) 스톡 이미지 위에서 동작한다.** AGS-102 등 포크에 의존하지 않는다. | BaseOS가 `System/frontend` 계약으로 임의 프론트엔드를 직접 실행한다. AGS-102는 BaseOS가 slot을 지원하기 전의 임시 포크로, 공식 가이드가 "optional"로 명시. |
| D-02 | **지원 기기는 BaseOS의 H700 타깃 중 RG28XX를 제외한 10종.** 개발 기준 기기는 RG SP(`rgsp`, 720×480). | RG28XX(480×640, 90° 회전)를 빼면 지오메트리가 640×480 / 720×480 / 720×720 세 가지로 줄어 단일 레이아웃으로 처리 가능. |
| D-03 | **에뮬레이션은 인프로세스 libretro.** RetroArch를 쓰지 않는다. 호스트는 코어 무관(core-agnostic)으로 만들고, 코어별 특수 처리는 `quirks` 모듈로 분리한다. | BaseOS엔 RetroArch가 없어 외부 런처는 RA 빌드 유지 부담을 떠안는다. 되감기·스테이트 UI·뚜껑 세이브 등 slot의 정체성은 인프로세스여야 성립. 같은 하드웨어에서 NextUI(minarch)가 멀티시스템 인프로세스를 검증했다. |
| D-04 | **플랫폼은 GB, GBC, GBA, NES, SNES, MD, SMS 7종.** PS1 이상은 제외. | 전부 2D 소프트렌더·카트리지 기종. 디스크 컨트롤, HW 렌더, 대용량 스테이트 문제가 없다. |
| D-05 | **코어 5종:** mGBA(GB/GBC/GBA), gpSP(GBA 선택), FCEUmm(NES), snes9x(SNES), Genesis Plus GX(MD/SMS). | 코어 수 최소화. snes9x·GPGX는 비상업 라이선스 — 배포물에 라이선스·소스 동봉. |
| D-06 | **BIOS는 전부 선택.** `BIOS/` 평면 폴더에 gb/gbc/gba/sms BIOS를 두면 부팅 로고 재생, 없으면 HLE. 크기+첫 바이트로 진위 판정, 체크섬 불사용. | 원본 정책 계승. 지역별 덤프 배제 문제 회피. |
| D-07 | **UI는 원본의 "물건 은유"(선반·카트리지·슬롯·폴라로이드)를 유지·확장한다.** | 원본의 차별점. 7종 모두 실물 카트가 있어 은유가 자연스럽게 확장된다. |
| D-08 | **플랫폼별 슬롯 스킨(B안).** 플랫폼 전환 시 하단 포트 그래픽·카트 실루엣·삽입 애니메이션·효과음이 그 기종 것으로 바뀐다. 스킨은 데이터 테이블로 정의하고, 미완성 플랫폼은 GBA 스킨으로 폴백. | 만능 슬롯은 은유의 사실감을 깎는다. 데이터화하면 이후는 그림 작업만 남는다. |
| D-09 | **UI 레이아웃은 640×480 안전 영역을 화면 중앙에 두고, 남는 영역은 배경/선반 연장으로 채운다.** | 세 지오메트리의 교집합이 640×480. 기기별 분기가 UI 전체로 퍼지지 않는다. |
| D-10 | **셰이더는 내장 프리셋(LCD3x, sharp-bilinear, zfast-crt, scanline)부터.** 사용자 GLSL·`.glslp` 호환은 후순위. `.slang`은 미지원. | Mali G31 MP2에서 실용적인 셰이더는 단일 패스 프리셋군이 사실상 전부. |
| D-11 | **오버레이(베젤)는 플랫폼×지오메트리별 PNG.** 기본은 없음. | GB(3×=480×432), CubeXX 상하 여백 등에서 효용이 크다. |
| D-12 | **다국어를 처음부터 내장한다.** 포맷은 **Fluent(`.ftl`)**, en/ko 내장 + 카드 `System/Lang/`로 덮어쓰기. | GitHub 공개 배포 예정. Fluent는 번역 커뮤니티 표준이며 커스텀 함수를 지원한다. |
| D-13 | **한국어 조사·어순을 위한 메커니즘을 i18n 계층에 내장한다.** `JOSA()` 함수, 문장 조각 결합 금지, 버튼캡·아이콘도 `BTN()` 자리표시자(스팬)로 처리. | 나중에 붙일 수 없는 부류. 같은 훅이 관사·복수형 등 다른 언어에도 쓰인다. |
| D-14 | **폰트는 문자 체계(script)별 폴백 체인.** UI 라틴 → 한글 → 가나·한자(CJK) → 아이콘. 한글·CJK는 **Noto Sans KR 서브셋**(라틴+한글+가나+KS X 1001 한자, ≈17k 글리프) 1개를 항상 내장하고 지연 로딩. 언어팩 `font=`는 UI 본문 선호 폰트만 지정. 대체 라벨 인쇄에도 같은 체인. | 게임 제목(파일명)에 일본어·한자가 나오므로 CJK 커버리지는 언어 설정과 무관하게 필요. Pretendard는 한자가 없어 제외. fontdue는 로드 시 전 글리프를 파싱하므로 글리프 수를 서브셋으로 제한. |
| D-15 | **아날로그 스틱은 입력 계층에서 일반 축 이벤트로 읽어 올린다.** 핫키 지정 등 활용은 보류. | 지금 읽어두면 나중에 입력 계층을 다시 열 필요가 없다. |
| D-16 | **저장소는 `C:\SLOT2`에서 백지 시작.** 원본 `C:\Users\gyuha\slot-2`는 읽기 전용 참고. 원본 코드를 가져올 때는 파일 단위로 이식하고 MIT 고지를 유지한다. 제미나이의 RetroArch 런처 커밋은 폐기. | "완전히 재구성"과 크레이트 재편 때문에 upstream 머지가 성립하지 않는다. |
| D-17 | **빌드는 x86_64 네이티브 크로스컴파일.** `debian:bullseye` + `gcc-aarch64-linux-gnu`(glibc 2.31) Docker 이미지를 로컬·CI 공용. QEMU arm64 에뮬레이션 폐기. | 디바이스 빌드의 Rust 부분은 전부 `dlopen`이라 sysroot 불필요. C 코어만 크로스 gcc가 필요. |
| D-18 | **UI 반복 작업은 PC 호스트 빌드(창 모드)로 한다.** `SLOT2_GEOMETRY`로 세 지오메트리를 PC에서 확인. | 기기 없이 UI 대부분을 개발·검증. |

| D-19 | **데스크탑 매니지먼트 앱과 연동한다.** 연동은 SLOT2의 **명시적 "연동 모드"** 에서만 이루어진다: 카트 꺼내기(세이브 flush) → Wi-Fi 접속 → `System/manifest.json` 갱신 → 화면에 `<hostname>.local`/IP 표시 → 데스크탑이 `System/sync.lock` 생성·삭제 → 재스캔. 전송 계층은 BaseOS의 SFTP(dropbear)·USB 저장소 모드·SD 리더를 그대로 쓰고, 데스크탑 앱은 이를 "카드 루트" 백엔드로 추상화한다. 세이브는 `<플랫폼>/<stem>` 키로 양방향 동기화. | 유휴 시 비용 0. 플레이 중 전송은 프레임 경합보다 **파일 일관성**(열린 `.sav` 덮어쓰기, 반쪽 ROM 스캔)이 문제라 모드 분리가 필요. 전송 계층을 BaseOS에 맡기면 SLOT2에 네트워크 서버 코드가 들어오지 않는다. 내장 에이전트(HTTP+mDNS)는 v2에서 백엔드 추가로 대체 가능. |
| D-20 | **Wi-Fi AP 접속은 SLOT2가 소유한다.** 기본은 연동 모드에서만 접속(`wpa_supplicant` + `udhcpc` 실행), 설정으로 상시 접속 가능. 자격 증명은 데스크탑 앱이 카드에 쓰는 `System/wifi.toml`에서 읽고, 기기에서는 목록 선택만. | BaseOS는 드라이버·rfkill·`wlan0 up`·DHCP 이벤트 후 mDNS까지만 하고 wpa_supplicant는 띄우지 않는다(NextUI도 자체 소유). D-pad로 비밀번호 입력은 UX상 배제. 연동 모드 한정 접속은 배터리에도 유리. |

| D-21 | **치트코드 지원.** `System/cheats/<PLAT>/<stem>.cht`(RetroArch `.cht` 포맷)를 로드 시 `retro_cheat_set`으로 코어에 전달, 퀵 메뉴에서 항목별 on/off. 파일 작성·갱신은 데스크탑 앱(libretro-database 치트 컬렉션 활용). `quirks`가 코어별 형식을 사전 검증. | libretro 표준 API이고 5개 코어 모두 지원. 파싱·적용은 코어가 하므로 호스트 비용은 파일 읽기뿐. `.cht` 포맷을 쓰면 기존 치트 DB를 그대로 가져온다. |
| D-22 | **HDMI는 커널 미러링을 기본으로 지원한다**(비용 0, SLOT2 무개입). HDMI 전용 720p 출력(`Geometry::W1280H720` 추가)은 M6에서 실측 후 결정. 1080p는 대상 아님. | BaseOS가 HDMI를 지원하고 sunxi 디스플레이 엔진이 패널을 복제한다(확인 V-13). 안전 영역 설계(D-09) 덕분에 지오메트리 추가는 UI 재작업이 아니다. Mali G31에서 720p+단일 패스 셰이더는 가능 범위로 예상되나 측정 전엔 미확정. |

| D-23 | **인게임 메뉴를 둔다.** MENU 탭으로 열고(코어 정지·뮤트, 마지막 프레임 위에 패널), 항목은 계속하기 / 세이브 스테이트(스위처) / 치트 / 화면(스케일·셰이더·오버레이, 즉시 미리보기) / 코어(전환·quirks 옵션) / 기기(밝기·블루라이트·볼륨) / 꺼내기. 원본의 "MENU 더블탭 = 스위처"는 폐기, MENU 홀드=꺼내기와 SELECT 코드·L2/R2 제스처는 유지. 설정 계층은 전역 → 플랫폼 기본 → 게임별. | 원본은 게임 중 메뉴가 없고 제스처만 있었다(GBA 전용이라 가능). 7개 플랫폼·치트·셰이더는 게임별 조정이 필요. 더블탭을 두면 탭 판정이 늦어져 메뉴가 굼떠진다. |
