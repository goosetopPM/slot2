# SLOT2 작업 지침서 — Codex 설계·검토 / 대화형 코딩 에이전트 실행

시행: 2026-09-25. 목적은 Codex 이용한도와 전체 작업 비용을 줄이면서 검증 수준을 유지하는 것이다.
기본 방식은 **Codex가 명세 작성 → 사용자가 선택한 대화형 코딩 에이전트에 직접 전달 → 완료 후 Codex가 검토**다. 현재 실전 검증은 가재코드 대화형 도구를 사용한다. OpenCodex 자동 실행은 연결 안정화 전 기본 경로에서 제외한다.

## 1. 역할과 문서

| 담당 | 책임 | 기본적으로 하지 않는 일 |
|---|---|---|
| 사용자 | 작업 방향 결정, 명세·결과 전달, 필요한 승인, RG SP 실기 확인 | 로그 전문 복사, 매 단계 중계 |
| Codex | 요구 정리, 계약·범위·완료 기준, 필요한 독립 검토, 최종 판정 | 실행 중 반복 감시, 일상 구현·Pi 검증을 대신 진행 |
| 대화형 코딩 에이전트 | 사용자가 태스크 경로를 직접 전달; 필요한 조사, 구현, 관련 검사, 오류 수정, 결과 보고, 명세가 허용한 Pi 검증 | 범위 확장, 재귀 위임, 커밋·푸시, RG SP 실기 접근 |
| 셸·검증 도구 | 파일 검색·집계, 빌드·테스트, 종료 코드 기록 | 정상 결과를 설명하기 위한 불필요한 모델 호출 |

코딩 에이전트와 제공자·모델 이름을 구분한다. 현재 실전 작업은 사용자가 가재코드 대화형 도구에 직접 명령한다. OpenCodex는 설치 상태를 유지하되 30초 provider connect timeout이 반복되어 자동 실행 경로로 사용하지 않는다. 모델이나 전역 라우팅을 이 지침을 이유로 자동 변경하지 않는다.

문서마다 역할을 분리한다.

- `AGENTS.md`: 매 실행에 필요한 짧은 필수 규칙.
- 이 문서: 사람과 에이전트의 전체 운영 절차. 처음 도입하거나 절차가 헷갈릴 때 읽는다.
- `docs/HANDOFF-CODEX.md`: 현재 상태와 다음 작업. 과거 상태를 최상단에 누적하지 않는다.
- `tasks/NN-이름.md`: 해당 작업의 계약과 완료 기준.
- `tasks/NN-이름.worker-result.md`: 실행자의 결과와 증거.
- `tasks/NN-이름.result.md`: Codex의 최종 판정. 실행자의 성공 선언과 구분한다.
- `docs/DESIGN.md`, `docs/DECISIONS.md`: 설계 계약. 필요한 절만 읽는다.
- `docs/AGENT-OPERATIONS-LEGACY.md`: 과거 장애·bai-gjc 진단 자료. 평소에는 읽지 않는다.

사용자 지시가 우선한다. 확정된 D-결정 변경, 공용 설정 변경, 커밋·푸시 등 기존 승인 조건은 유지한다.

## 2. 한 작업 묶음의 흐름

### A. Codex에서 작업 정의

1. 현재 핸드오프 최상단과 관련 계약만 확인한다. 모든 과거 보고서를 다시 읽지 않는다.
2. 이미 수정된 파일과 진행 중인 작업을 확인하여 다른 작업을 덮어쓰지 않게 한다.
3. 크레이트 경계나 하나의 결과물 기준으로 태스크를 나눈다. 연관 수정은 묶되, 서로 다른 실행기 두 개처럼 독립 결과물은 별도 태스크로 둔다.
4. 수정 허용 파일, 금지 사항, 완료 명령 원문, 결과 경로를 태스크에 적는다.
5. 가능하면 Codex 계정의 5시간·주간 사용률을 전달 직전에 기록한다. 이 값은 작업별 소비량의
   기준선이며, 다른 창 사용과 한도 초기화가 섞이면 상한 또는 측정 불가로 판정한다.
6. 사용자에게 아래 전달 문구와 태스크 경로를 주고 **응답을 끝낸다**. 코딩 에이전트를 자동 실행하거나 감시하지 않는다.

사용자가 가재코드 대화형 작업에 전달할 문구:

```text
Read and execute C:\SLOT2\tasks\NN-name.md exactly. Treat that file as the complete
contract. Work directly without delegation. Do not commit, push, access hardware, or change
shared configuration. Before stopping, write C:\SLOT2\tasks\NN-name.worker-result.md.
```

`NN-name`은 Codex가 실제 생성한 경로로 바꿔 전달한다. Windows 입력 인코딩 문제를 피하기 위해
태스크와 전달 문구는 영문 ASCII를 기본으로 한다. 이 문구는 셸 명령이 아니라 가재코드 대화형
도구에 입력하는 요청이다.

Raspberry Pi 3B+ 검증이 필요한 태스크도 Codex가 직접 실행하지 않는다. Codex는 태스크에
`build/pi-test.ps1`의 대상 크레이트, `-Setup` 필요 여부, 성공 기준과 결과 요약 형식을 적고,
사용자가 그 태스크를 가재코드 대화형 도구에 전달한다. 이때만 위 전달 문구의 일반적인
`access hardware` 금지를 “지정한 Pi 검증만 허용, RG SP·adb·Samba·SD 카드는 금지”로 좁힌다.
Pi 주소는 `goosetop@192.168.68.166`이며, 명세에 없는 SSH/SCP 명령이나 원격 정리는 허용하지
않는다.

가재코드 셸에서 Windows 절대경로의 역슬래시가 사라질 수 있으므로 Pi 스크립트는 프로젝트
루트에서 `powershell -File ./build/pi-test.ps1 ...`처럼 상대경로와 슬래시로 실행한다. 크로스
빌드와 원격 실행은 5분을 넘길 수 있으므로 최초 호출부터 태스크 전체 허용시간에 맞는 도구
타임아웃을 준다. 경로 구문 실패, 잘못된 옵션, 도구 타임아웃 중단도 태스크 시도 횟수에 포함한다.

### B. 사용자가 대화형 코딩 에이전트에서 실행

1. 사용자가 가재코드 등 선택한 대화형 코딩 에이전트에 태스크 파일 절대경로를 직접 전달한다. 태스크별 새 작업 컨텍스트를 기본으로 하고 Codex 대화 전문은 전달하지 않는다.
2. 실제 읽은 파일과 명세에 따라 구현한다. 명세에 없는 큰 설계 변경이 필요하면 질문 또는 미완 보고를 남긴다.
3. 관련 테스트와 소비 크레이트 검사를 수행한다. 라이브러리 검사만으로 앱 호출부까지 성공했다고 판단하지 않는다.
4. 실패하면 원인과 수정 내용을 기록하고 남은 시도 범위에서 보완한다.
5. 마지막 코드 변경 뒤 필요한 검증을 순차 수행한다. 같은 소스/target을 쓰는 수정·빌드를 겹치지 않는다.
6. 성공·실패·부분 완료를 구분한 결과 파일을 남긴다. 실패하거나 중단되어 보고서를 못 만들었으면 사용자는 실패 사실과 로그 경로만 Codex에 전달한다.

실행 예산은 첫 응답 최대 5분, 전체 최대 45분이다. 빈 로그는 중단 사유가 아니다. 이 예산은 운영 기준이며 모든 도구에서 강제 타임아웃이 구현된 것으로 가정하지 않는다. 시간 초과 시 자동 재시도하지 않고 현재 상태를 보고한다.

### C. Codex에서 회수·판정

사용자가 완료 후 전달할 문구:

```text
가재코드 작업이 끝났습니다.
C:\SLOT2\tasks\NN-이름.worker-result.md를 검토하고 최종 판정해 주세요.
필요한 diff와 검증 증거만 확인해 주세요. 다음 기능에는 아직 착수하지 마세요.
```

Codex는 보고서 → 변경 파일 목록 → 중요한 diff → 필요한 검증 증거 순으로 읽는다. 실행자의 성공 선언만으로 통과시키지 않는다. 반대로 증거가 충분한 검사를 이유 없이 다시 돌리지 않는다.
판정 직후 사용률을 다시 읽고 기준선과 비교한다. 증가분은 해당 작업의 정확한 토큰량이 아니라
**Codex 소비 상한**으로 기록한다. 창이 초기화됐거나 다른 작업이 섞였으면 수치 비교를 생략한다.

- **통과:** 계약과 필요한 검증을 충족했다.
- **미완:** 구현은 있으나 필요한 검사·사용자 결정·실기 확인이 남았다.
- **실패:** 계약 위반, 검증 실패, 또는 실행 불완전으로 목표를 달성하지 못했다.

보완이 필요하면 남은 시도 횟수와 수정할 지점을 좁혀 사용자에게 전달한다. 통과하면 최종 결과와 핸드오프를 갱신한다. 커밋·푸시는 별도 사용자 요청이 있을 때만 수행한다.

보완 시도 보고서는 최초 보고서 전체를 반복하지 않는다. **수정한 지점, 추가한 회귀 테스트,
최종 검증 결과만 20~30줄 안팎의 delta로 갱신**한다. Codex도 재검토 때 이 delta와 관련 diff만
먼저 읽고, 변경 범위가 넓어졌거나 증거가 모순될 때만 최초 보고서와 전체 파일로 확장한다.

## 3. 태스크와 결과의 최소 양식

태스크 파일:

```markdown
# Task NN — 목표
- 현재 상태/기존 변경:
- 기대 동작과 관련 계약(파일·절):
- 수정 허용 파일:
- 범위 밖/금지 사항:
- 완료 기준 명령 원문:
- 성공 판정 기준:
- 이전 시도 횟수 / 이번 허용 횟수:
- 결과 경로: C:\SLOT2\tasks\NN-이름.worker-result.md
```

작업자 결과 파일:

```markdown
# Task NN 실행 결과
- 판정: 성공 / 실패 / 부분 완료
- 시도: 누적 N/2
- 변경 파일과 변경 이유:
- 검증: 명령 / 종료 코드 / 핵심 결과 / 로그 경로
- 검증 후 코드 수정 여부:
- 실패 원인 또는 남은 항목:
- 계약이 잘못됐다고 판단한 지점:
- 실행 시간·토큰 보고값(알 수 없으면 미확인):
```

명세는 우선 1~2천 토큰, 결과는 우선 30줄 이내를 목표로 한다. 필수 계약·실패 증거를 길이 제한 때문에 생략하지 않는다. 로그와 코드 전문은 결과 파일에 붙이지 않는다.
보완 시도는 기존 항목을 다시 나열하지 않고 attempt 번호, 수정 delta, 새 회귀 증거, 최종 검증만
남긴다.

## 4. 컨텍스트와 에이전트 사용

- 정해진 파일 읽기·검색·명령 실행에는 셸을 우선한다. 판단이 필요한 부분만 모델에 맡긴다.
- 전체 저장소 읽기 대신 `rg`로 경로·심벌을 찾고 필요한 주변만 읽는다. `git diff --stat` 후 관련 diff를 본다.
- 작업 묶음이 바뀌면 새 컨텍스트를 사용한다. 같은 결함 보완은 기존 작업자에 짧은 지시로 이어 재탐색을 줄일 수 있다.
- 기본 실행 작업자는 1개다. 필요할 때 한정 조사나 독립 리뷰를 별도 에이전트에 맡긴다. 에이전트 수 자체를 절감 목표로 삼지 않는다.
- 새 에이전트에는 전체 대화 대신 자급적인 작업 명세를 전달한다. 해당 클라이언트가 지원하는 컨텍스트 상속 제어를 확인해서 사용한다.
- Codex 서브에이전트도 계정 한도를 소비한다. 모델·추론 강도가 부모에서 상속될 수 있으므로 비용이 낮다고 가정하지 않는다.
- OpenCodex 내 자동 위임과 Codex→OpenCodex 자동 연결은 별도 검증 후 도입한다. 현 기본 운영에는 필요하지 않다.
- 사용자 지정이 없으면 다중 작업자·재귀 위임·모델 변경을 자동으로 확장하지 않는다. 작은 수정에는 새 에이전트 기동보다 단순 직접 처리가 저렴한지 판단한다.

## 5. 검증과 실패 처리

기능 코드 작업 묶음의 최종 검증은 아래 명령을 순차 수행한다. 같은 코드 상태에서 이미 성공한 명령은 근거를 기록하여 재사용한다. 문서만 바꾼 작업에는 Rust 전체 검사를 돌리지 않는다.

```powershell
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
powershell -File build/dist-device.ps1
```

- 테스트: 종료 코드와 passed/failed 합계 확인. 최신 확인 기준은 핸드오프에 기록한다. 테스트 감소는 회귀 여부를 보고한다.
- clippy: 종료 코드 0 확인.
- dist: 종료 코드 0 및 마지막 성공 표시 `==> done` 확인. `-Adb`를 붙이지 않는다. 배포 이미지 빌드는 실기 검증을 대신하지 않는다.
- 관련 소스를 바꿨거나 실패 원인이 남아 있으면 영향받는 검사를 다시 수행한다.
- 실패·중단한 실행도 횟수에 포함한다. 이름을 바꾸거나 모델을 바꿔 같은 태스크의 2회 제한을 초기화하지 않는다.
- 2회 실패 시 자동 실행을 멈추고 원인·남은 파일·다음 선택지를 보고한다. 새 사용자 지시 전까지 세 번째 시도하지 않는다.
- 연결 장애와 코드 결함을 구분한다. 프록시가 살아 있다는 사실만으로 제공자 응답이나 코드 품질까지 정상이라고 판단하지 않는다.
- 계약이 틀리면 테스트에 맞춘 상수·패딩·린트 억제로 감추지 말고 문제를 보고한다.

## 6. 보호해야 할 것

- 실기는 사용자만 확인한다. 에이전트는 adb, Samba S:, SD 카드에 접근하지 않는다.
- 공용 B.AI YAML과 사용자 Codex 전역 설정을 프로젝트 실행 편의를 위해 임의 변경하지 않는다. 키 값을 출력하지 않는다.
- `D:\Refrom\SpruceOS\dist_final\pack`은 읽기 전용이다. 상용 ROM은 커밋하지 않는다.
- 기존 미커밋 변경을 보존한다. 파괴적 정리·원상복구로 작업 트리를 깨끗하게 만들지 않는다.
- 권한 오류를 샌드박스 무력화로 해결하지 않는다. 필요한 범위의 권한과 실제 원인을 확인한다.

## 7. 비용 기록과 도입 상태

Codex 계정 사용률, 코딩 에이전트의 입력/출력/캐시 토큰, 실제 제공자 비용은 별도 지표다.
사용자가 Codex 사용량만 요청하면 코딩 에이전트 토큰은 제외한다. 캐시 토큰을 입력에 다시 더하지
않고 미확인 값은 0으로 기록하지 않는다. 다른 창 사용과 한도 리셋이 있으므로 계정 사용률 차이를
해당 작업의 정확한 청구량으로 단정하지 않는다.

우선 운영 목표는 **Codex 명세 작성과 최종 검토 두 번의 사용자 왕복**이다. 실패·설계 변경은 예외로 기록한다. 시간·토큰 외에도 수정 횟수와 검증 통과 여부를 함께 평가한다.

도입 시점 상태:

- OpenCodex 경유 읽기 도구 왕복은 성공했지만 제공자 연결 시간 초과도 발생했다. 장기 안정성을 보장하지 않는다.
- Task29의 규칙 축약 실험은 동일 읽기 작업 input 보고값 약21% 감소. 실제 비용·구독 한도 절감률은 미측정.
- Task33은 가재코드 대화형 실행 1회로 약 7분 만에 구현·검증을 완료했다. Codex는 명세 작성과
  결과 판정만 수행했다. 주간 사용률은 46%에서 48%로 최대 2%p 증가했으나 다른 사용이 섞일 수
  있어 Task33의 정확한 소비량으로 보지 않는다. 같은 시기의 자동 OpenCodex 실패 구간은 주간
  43%에서 46%로 3%p 증가했고 5시간 창은 79%에서 96%로 증가했다.
- `build/run-bai-worker.ps1`, `build/verify-workspace.ps1`은 미검증 초안이다. **본 지침의 실행 수단으로 사용하지 않는다.**
- 기존 수동 CLI 연결 기록은 `tasks/26-opencodex-worker.result.md`에 있다. 전체 작업 환경 설치가 필요한 경우 별도 설정 태스크로 처리한다.
- 당장은 수동 중계로 실작업을 검증한다. 자동 실행기 수리나 에이전트 대량 도입을 개발 재개의 전제조건으로 삼지 않는다.

운영 근거와 측정 한계는 `tasks/28-workflow-cost-review.result.md`부터 `tasks/30-opencodex-workflow-options.result.md`까지의 기록에 남겨 두었다. 평소 작업자는 이를 전부 읽을 필요가 없다.
