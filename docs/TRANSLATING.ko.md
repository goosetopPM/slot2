# 번역 가이드

English: [docs/TRANSLATING.md](TRANSLATING.md)

SLOT2의 화면 문구는 전부 Fluent `.ftl` 파일에서 온다. 코드에는 사용자에게 보이는 문자열이 없고,
문장을 조각내어 이어 붙이지도 않는다. 이 문서는 새 언어를 더하거나 기존 번역을 고치는 사람이 그대로
따라 할 수 있는 절차와 규칙을 적는다.

## 1. 파일과 관계

| 위치 | 무엇 | 완전성 |
| --- | --- | --- |
| [assets/lang/en.ftl](../assets/lang/en.ftl) | 기준(canonical) 언어. 모든 key의 원본 문장 | 모든 key |
| [assets/lang/ko.ftl](../assets/lang/ko.ftl) | 내장 한국어 | 영어와 **같은 key 125개**, 변수·버튼 자리표시자 동일 |
| `<카드>/System/Lang/<code>.ftl` | 카드가 넣은 언어 또는 내장 언어 덮어쓰기 | **일부 key만 있어도 된다** |

- 파일은 UTF-8, 확장자는 `.ftl`, 이름은 언어 코드(`ja.ftl`, `pt-BR.ftl`)다. 확장자·이름은 대소문자를
  구분한다.
- 카드 pack은 내장 pack 위에 얹힌다. 같은 key가 양쪽에 있으면 **카드가 이긴다**. 카드가 없는 key는
  내장 언어에서, 내장에도 없으면 영어에서 온다.
- 카드 전용 언어(내장에 없는 code)는 영어 위에 얹힌다. 일부 key만 있어도 되고, 나머지는 영어로 표시된다.
  내장 `ko`처럼 전체를 채워야 하는 것은 **내장 언어만**이다.
- 카드는 `System/Lang/en.ftl`을 넣어 영어 자체를 덮어쓸 수도 있다. 그러면 그 카드에서는 다른 모든
  언어의 fallback이 그 영어가 되므로, 저장소를 건드리지 않고 그 카드에서만 기준 문장을 고칠 수 있다.
- 카드에 `<code>.ftl`을 넣으면 재부팅 없이 언어 선택 화면 목록에 나타난다(목록은 `System/Lang`을 다시
  읽어 만들고, load에 실패한 pack은 목록에서 빠진다).

## 2. 절차

1. `assets/lang/en.ftl`을 복사해 `System/Lang/<code>.ftl`로 둔다. 카드에 직접 넣는 경우 이 파일 하나로
   끝이고 코드 수정이 필요 없다.
2. `lang-name`을 **그 언어가 스스로를 부르는 이름**으로 적는다(예: `日本語`, `Português`). 언어 선택
   화면의 행 이름이 이 값이다. 영어 이름을 번역해 넣지 않는다.
3. 문장을 하나씩 번역한다. key 이름, `$변수`, `{ BTN("...") }`, `{ JOSA(...) }`는 그대로 두고 그 사이의
   말만 바꾼다.
4. 검증 명령을 돌린다(§7). 카드 pack은 아래 내장 pack 계약 테스트의 대상이 아니므로, 카드에서는 언어
   선택 화면에 나타나는지와 문장이 잘리는지 눈으로 확인한다.

내장 언어를 새로 추가하려면 위 `.ftl`을 `assets/lang/`에 넣고
[EMBEDDED](../crates/slot2-i18n/src/lib.rs) 목록에 `(code, include_str!(...))`를 한 줄 더하며,
[pack_contract.rs](../crates/slot2-i18n/tests/pack_contract.rs)의 완전성 검사 대상에도 그 code를
추가한다. 이건 코드 변경이므로 관리자가 pack과 함께 검토한다. 카드 전용 언어에는 코드 변경이 필요 없다.

## 3. 폰트 (`lang-font`)

- `lang-font`는 그 언어의 UI 본문 선호 폰트 **파일명 하나**다. 경로가 아니다.
  - 허용: `NotoSansKR-Regular.otf`, `MyFont.ttf`
  - 금지: `System/Fonts/MyFont.ttf`, `../MyFont.ttf`, `sub/MyFont.ttf`, `.`, `..`
  - `/`와 `\`를 모두 거부한다. Windows와 Linux가 구분자를 다르게 다루기 때문이며, 구성 요소가 둘 이상인
    이름도 거부한다.
  - 선호 폰트가 없으면 key를 생략한다. 내장 영어의 `lang-font = { "" }`는 canonical metadata를
    명시적으로 비워 둔 예외다.
  - 확장자를 바꾸거나 대소문자를 보정하지 않는다. pack에 적은 이름 그대로 찾는다.
- 찾는 순서: 카드의 `System/Fonts/` → 빌드에 들어 있는 폰트 폴더. 처음 발견한 파일을 쓴다.
- 그 파일은 화면에 처음 필요할 때 읽는다(지연 로딩). 파일이 없거나 이름이 안전한 단일 파일명이 아니면 그
  줄은 무시되고 기본 체인(`OpenSans` → 한글·CJK `Noto Sans KR`)으로 그린다. 로그에 한 줄만 남고, 폰트
  문제로 언어 전환이나 화면 표시가 실패하지는 않는다.
- 폰트를 저장소에 넣을 때는 라이선스를 함께 넣는다. 이미 들어 있는 폰트의 고지는
  [assets/fonts/NotoSansKR-OFL.txt](../assets/fonts/NotoSansKR-OFL.txt),
  [assets/fonts/OpenSans-OFL.txt](../assets/fonts/OpenSans-OFL.txt)이고, 배포본에서는
  `System/licenses/`에 함께 복사된다(About 화면의 "코어 및 글꼴 고지" 줄이 가리키는 폴더). 상용 폰트나
  라이선스가 불분명한 폰트는 저장소에 넣지 않는다.

## 4. 문장 규칙

- **문장은 통째로.** 코드가 조각을 이어 붙이지 않는다. `"저장했습니다"` 같은 조각을 만들지 말고 완성된
  문장 하나를 key에 넣는다.
- **변수 이름은 그대로.** `$title`을 `$제목`으로 바꾸면 실패한다. 값이 들어갈 자리만 옮긴다.
- **어순은 언어가 정한다.** `Saved { $title } to slot { $n }`은 한국어에서
  `{ $n }번 슬롯에 { JOSA($title, "을/를") } 저장했습니다`가 된다. 변수의 등장 횟수·순서와 버튼 자리의
  문장 내 위치는 같을 필요가 없다. en/ko에서 같아야 하는 것은 변수 **이름의 집합**과 BTN id의
  **순서·개수**다.
- **변수를 잃거나 새로 만들지 않는다.** 같은 key의 en/ko는 `$변수` 집합과 `BTN` id 목록이 정확히
  같아야 한다(내장 pack 계약 테스트가 검사한다).
- 제품명(`SLOT2`), 코어 이름(`mGBA`, `gpSP`…), 경로(`System/cores`, `System/licenses`), 버전·기기
  이름·언어 코드 같은 기술 식별자는 번역하지 않는다.

## 5. 버튼 (`BTN`)

버튼은 문장 안의 자리표시자다. 그 자리에 실제 버튼 캡이 그려진다.

```ftl
hint-eject = Hold { BTN("menu") } to eject
hint-eject = { BTN("menu") } 길게 눌러 꺼내기
```

- 위치는 언어가 정한다(문장 앞이든 뒤든). 버튼을 다른 버튼으로 바꾸거나 개수를 바꾸면 안 된다.
- 유효한 id(대소문자 구분 없음, 원본 목록은 [button.rs](../crates/slot2-input/src/button.rs)):

| id | 캡 | id | 캡 | id | 캡 |
| --- | --- | --- | --- | --- | --- |
| `a` | A | `l1` | L1 | `select` | SELECT |
| `b` | B | `r1` | R1 | `start` | START |
| `x` | X | `l2` | L2 | `menu` | MENU |
| `y` | Y | `r2` | R2 | `power` | POWER |
| `up` / `down` | ↑ / ↓ | `left` / `right` | ← / → | `vol+` / `vol-` | VOL+ / VOL− |

- 없는 id를 쓰면 화면에 `[?turbo]` 같은 글자가 그대로 나온다. 오타를 위한 안전망일 뿐이므로 내장
  pack에서는 허용하지 않는다(테스트가 실패한다).
- **literal 캡 금지.** `[A]`, `[MENU]`, `[L1]`처럼 대괄호로 직접 적지 말고 항상 `BTN("...")`을 쓴다.
  `[A]`는 폰트에 있는 글자일 뿐이고, 버튼 캡이 아니라 문장 부호로 그려진다. 일반 문장에서 `[`를 쓰는 것
  자체는 막지 않는다.

## 6. 조사 (`JOSA`) — 한국어만

한국어는 앞 단어의 받침에 따라 조사가 달라진다. 게임 제목처럼 런타임에 정해지는 값 뒤에 조사를 붙일
때는 `JOSA`를 쓴다(규칙 구현은 [josa.rs](../crates/slot2-i18n/src/josa.rs)).

```ftl
cart-inserted = { JOSA($title, "을/를") } 꽂았습니다
platform-switched = { JOSA($platform, "으로/로") } 전환했습니다
cheat-load-failed = { $title }의 치트를 읽지 못했습니다
```

- 첫 인자는 그 문장에 이미 있는 변수여야 한다(`$title`). 리터럴 문자열은 쓸 수 없다.
- 지원하는 쌍: `을/를`, `이/가`, `은/는`, `과/와`, `으로/로`, `아/야`, `이여/여`.
  `으로/로`는 ㄹ받침도 `로`로 처리한다. 숫자로 끝나는 값은 읽는 소리로 판정한다.
- 받침을 알 수 없는 값(영문 제목 등)에는 `을(를)`처럼 병기형으로 나온다. 이건 의도된 동작이다.
- **고정 조사를 변수에 직접 붙이지 않는다.** `{ $title }을 저장했습니다`는 "포켓몬을"과
  "테트리스를" 중 하나에서 틀린다. JOSA를 쓰거나, 조사가 필요 없는 문장으로 다시 쓴다.
  - 다시 쓰는 예: `{ $title }을 저장했습니다` → `{ $n }번 슬롯에 저장했습니다`
    (제목을 문장에서 빼면 조사 문제가 사라진다. 정보를 잃지 않는 재문장은 언제나 허용된다.)
- `의`, `에`, `에서`처럼 받침에 따라 모양이 변하지 않는 조사는 변수 뒤에 바로 붙여도 된다
  (`{ $title }의 치트`). 변하는 조사(`은/는`, `이/가`, `을/를`, `으로/로`, `과/와`, `아/야`)만 JOSA가
  필요하다.
- 영어 pack에는 `JOSA`를 쓰지 않는다. 조사는 한국어 pack의 것이다(테스트가 강제한다).

## 7. 검증

번역을 마치면 저장소 루트에서:

```text
cargo test -p slot2-i18n --test pack_contract
cargo test -p slot2-i18n
```

`pack_contract`는 내장 `en`/`ko`를 검사한다:

- 두 pack이 같은 key 집합을 가지고 중복 id가 없으며, key가 정확히 125개다.
- 빈 값이 없다. 예외는 fallback pack의 `lang-font` 하나뿐이다.
- 같은 key의 `$변수` 집합이 두 pack에서 일치한다.
- `BTN` id 목록이 일치하고, 각 id가 프론트엔드가 아는 버튼이다.
- `JOSA`는 한국어만 쓰고, 그 문장에 이미 있는 변수와 지원하는 일곱 쌍 중 하나만 쓴다.
- 버튼 캡을 대괄호로 직접 적은 pack이 없다.
- 런타임이 제공하지 않는 함수를 부르지 않는다(`BTN`, `JOSA`, `NUMBER`, `DATETIME`).
- 두 pack이 실제로 load되어, 모든 기준 key가 `[key]` 표시 없이 format된다.

카드 pack은 일부 key만 있어도 되므로 이 테스트의 대상이 아니다. 카드에서는 언어 선택 화면과 실제
화면에서 문장이 잘리지 않는지 눈으로 확인한다.

## 8. 실패했을 때의 동작

- **key가 없으면** 영어로 표시된다. 화면이 비거나 빈 문장이 그려지지 않는다. 영어에도 없으면 그 key가
  `[key]`로 보이게 그려진다(panic은 없다).
- **문법이 틀린 pack은 load에 실패한다.** 시작 시 요청한 언어가 그 pack이면 영어로 부팅하고 카드의 설정
  값은 그대로 남는다. load에 실패한 pack은 언어 선택 화면 목록에서 빠진다. 전환할 수 없는 행은 지킬 수
  없는 약속이기 때문이며, 모든 빌드에 들어 있는 영어만 예외다.
- **실행 중 선택이 실패하면** 이전 언어를 유지하고 화면에 알린다. 선택한 언어는 새 pack이 실제로 load된
  뒤에야 카드에 기록되므로, 카드가 화면이 말하지 않는 언어를 가리키는 일은 없다.
- **일부 key만 있는 pack은 정상이다.** 나머지는 내장 언어 → 영어 순으로 채워진다.

## 9. 아직 없는 것

- 번역을 돕는 GUI 도구, 자동 번역, 용어집 강제는 없다. 이 문서가 전부다.
- 언어 **목록**(picker의 행 순서)은 locale 정렬 없이 언어 코드의 단순 순서다. 이 문서가 다루는
  `System/Lang/<code>.ftl` 파일명 규칙은 번역 pack의 것이고, ROM 파일명 규칙과는 별개다.
- ROM 제목과 파일명의 정렬·특수문자 처리는 [DESIGN.md](DESIGN.md) §8~§9가 정본이다: 제목은 로케일
  collation·자연수 정렬·대소문자 folding 없이 Unicode scalar value 순서로 정렬하고, 파일명에서는 마지막
  허용 확장자 하나만 떼며 유효한 UTF-8 stem의 문자를 그대로 보존한다(정규화·sanitize·rename 없음). 번역자는
  ROM 이름을 바꿀 필요가 없고, 바꾸면 세이브·라벨·스테이트 키도 함께 바뀐다.
- Noto Sans KR 서브셋 생성(`tools/subset-font.sh`)은 아직 없다. 지금 배포되는 폰트는 저장소의 원본
  `NotoSansKR-Regular.otf`다.
- 실기에서의 전 화면 한국어 확인(M5 Acceptance)은 별도 항목이다.

## 10. 기여하기

- 새 내장 언어를 함께 준비하거나 논의가 필요한 변경은
  [번역 양식](../.github/ISSUE_TEMPLATE/translation.yml)으로 알린다. 기계·AI 도움을 썼다면 그 사실과
  검토한 사람을 함께 적는다. 밝히는 것은 환영하며 금지되지 않는다.
- 카드 전용 pack은 이슈도 코드 변경도 필요 없다. `System/Lang/<code>.ftl`을 만들어 카드에서 시험한다.
- 내장 언어 기여는 현재 소스가 요구하는 파일을 확인한다. 즉 `assets/lang/`의 pack,
  [EMBEDDED](../crates/slot2-i18n/src/lib.rs)의 한 줄,
  [pack_contract.rs](../crates/slot2-i18n/tests/pack_contract.rs)의 code다. §7 명령을 돌린 뒤 검토를
  요청한다.
- 수정 기여는 바뀌는 key와 그 문장이 나오는 문맥을 함께 적는다. 문맥 없이는 번역을 판단할 수 없다.
- 누가 검토했고 어디서 온 문구인지 기록한다. 스스로를 프로젝트의 저자라고 소개하거나, 저작권 소유나
  법적 결론을 대신 주장하거나, 도움을 밝힌 것을 라이선스 허여로 해석하지 않는다.
- 폰트와 자산은 재배포 가능한 원본 라이선스 전문을 함께 넣는다. ROM, BIOS 파일, 공유 권한이 없는 게임
  화면 스크린샷, 비밀, 생성된 빌드 출력, 카드 데이터는 포함하지 않는다.
- 테스트를 약화시키거나, 없는 제품 동작을 만들어 내거나, 기술 식별자를 번역하거나, 번역을 통과시키려고
  영어 의미를 바꾸지 않는다. 지금 문장 그대로는 번역할 수 없다면 그 사실을 이슈에 적고 canonical 영어도
  함께 바꾼다.
